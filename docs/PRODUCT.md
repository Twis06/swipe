## Platform
web

The platform metadata describes the existing browser surfaces. Swipe also includes an experimental native macOS menu-bar app; its scope and local runtime requirements are documented below. The web design system remains authoritative for the browser surfaces.

## Users and purpose
Swipe explores microphone-based finger-swipe input on the left speaker grille of a 14-inch M3 Pro MacBook Pro. The current recognizer uses an MFCC8 reference bank from three built-in-microphone sessions, with a legacy matcher for uncertain results. Browser surfaces support live preview, guided isolated-gesture collection, and continuous 15-second recording. The native app maps discrete up/down swipes to local Mac actions. The owner found the browser preview usable in live testing; native recognition accuracy and transfer to other users or setups have not been established.

## Scope
The short-clip collector prompts swipe up/down and captures microphone audio with labels, including idle and typing negatives. Short-clip collection starts only after user microphone connection and a separate built-in-microphone confirmation. Preserve session/block provenance; avoid model accuracy claims before actual evaluation.

The continuous recorder lets the user choose a microphone, alternating cues or free up/down movement, and optional notes. Start requests microphone access, then gives a three-second countdown before capturing one uninterrupted 15-second take. Cued mode displays silent up/down prompts every 1.5 seconds; free mode follows the user's own pace. Capture ends automatically and disconnects the microphone before saving. Cancel or hiding the tab discards an unfinished take and releases the microphone. A save failure keeps the finished audio in page memory; Retry saving resubmits the same take, so the page must stay open until it succeeds. A saved-take confirmation and recording ZIP link appear after a successful save. Prompt metadata describes intended movements and displayed cue times, not verified gesture directions or boundaries; free movement remains an unlabeled sequence for later review.

The localhost-only live preview starts listening only when the user selects Start preview. It shows Up (toward the screen), Down (toward the palm rest), or Uncertain, with visible listening status and a short recent-results list. Preview audio and results are transient and are not saved to disk. Optional keyboard output maps accepted swipes to a key or modifier shortcut in the active macOS app. It starts disarmed and requires Accessibility permission, Start preview, and Enable keys. Stop listening or leaving the page releases the microphone and disables keys. Hiding the tab stops recognition unless key output is explicitly enabled, so switching to a target app works. The server disables key output after a 20-second lost-connection timeout. This remains an experimental preview, not a validated everyday input device; scores are not presented as calibrated confidence percentages.

The native SwiftUI/AppKit app provides a settings window and persistent menu-bar control. Each direction maps independently to volume up/down, mute/unmute, lock screen, system sleep, display sleep, a recorded keyboard shortcut, or no action. Volume uses the current output device and an adjustable step; devices without software volume or mute controls report an error. Defaults are up for volume up and down for volume down. Mappings and volume step persist, but every launch begins paused. Start listening requests microphone permission and selects the built-in input without changing the system default. After one second of background checking, the user swipes once, lifts their finger, and waits for the result. Only accepted, non-overlapping predictions trigger actions; uncertain/background results do nothing. Mappings cannot change while listening. Closing the settings window preserves an explicitly started listener; Pause and Quit release the microphone and stop the recognizer. Lock, system sleep, and display sleep pause before dispatch and require a fresh Start listening afterward. Keyboard shortcuts and lock require Accessibility permission, requested through the user's Allow access action; volume/mute and sleep actions do not.

## Implementation decisions
The browser surfaces use a local Python standard-library server and plain HTML/CSS/JavaScript. The collector was chosen to avoid dependencies; the learned preview uses the project's analysis environment, as documented in README.md. Each pilot has 28 clips in two randomized blocks. The short-clip collector saves two-second mono WAV clips and JSON metadata in the project data folder. Each continuous take saves one 15-second mono Float32 WAV and session JSON containing the mode, microphone settings, notes, planned and displayed prompt timelines, and the explicit need to review gesture labels. Displayed cue times estimate audio-relative presentation time, not measured finger onset. Both recording workflows save inside the project data folder. A cloud-sync provider may sync those files if the project is in a synced directory. The app itself has no external network service. The preview processes audio in memory on this Mac and leaves saved recording sessions unchanged.

The native app requires macOS 14 or later and Swift 6 or later to build. A dedicated Audio Queue input selects the built-in microphone by device UID and delivers 48 kHz mono Float32 samples without changing system defaults. A frame-progress watchdog reports stalled capture; Swift ports the existing 128-frame early/fallback capture logic and gates duplicate results. A private stdin/stdout Python child runs the existing PreviewService and verified model banks during listener startup and use. It requires this checkout and its external `.venv`; the ad-hoc-signed local bundle does not embed Python or provide a standalone distribution. No browser, HTTP server, runtime download, or saved microphone recording is involved. Synthetic capture parity checks establish software agreement with the browser worklet, not measured recognition accuracy through the native microphone path. See macos/README.md for setup and checks.
